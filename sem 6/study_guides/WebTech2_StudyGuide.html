Server-Side Programming

1.1 What is Server-Side Programming? ★★★

When you visit a website, some processing happens in your browser (client-side — HTML, CSS, JS) and some happens on the web server (server-side). Server-side programming means writing code that runs on the server, generates dynamic content, and sends it back to the client.

Simple Analogy Think of a restaurant. The menu you read is client-side (static). But the kitchen that prepares your food based on your order is server-side (dynamic, based on input).
📋 Exam Alert — Asked in 2022 and 2024 "What benefits does server-side programming bring?" — Write a structured list with brief explanation of each point.

Benefits / Advantages

  • Dynamic Content Generation — Pages generated at runtime based on user input or database data, unlike static HTML.
  • Database Integration — Server can query databases and return personalized results to each user.
  • Security — Sensitive logic (authentication, payment processing) stays on the server, never exposed to the client.
  • Session Management — Server can track users across multiple requests using cookies, hidden fields, or URL rewriting.
  • Business Logic Centralization — Rules are written once on the server, not duplicated across clients.
  • Platform Independence — The client only needs a browser regardless of OS.
  • Reduced Client Load — Heavy computation happens on the server, not on potentially weak client devices.

One of the most repeated comparison questions. Know it cold.

📋 Exam Twist — 2023 Paper "Compare client-side and server-side validation of forms." — Client-side validation improves UX but can be bypassed. Server-side validation ensures data integrity and cannot be bypassed. Both should always be used together.
1.3 Web Application & Directory Structure ★★★

A web application is a collection of web resources (HTML, Servlets, JSPs, static files, configuration) packaged together and deployed on a server like Apache Tomcat.

MyWebApp/ ← Root of web application │ ├── index.html ← Static pages, JSPs (directly accessible by browser) ├── style.css │ └── WEB-INF/ ← PROTECTED — NOT accessible by browser directly │ ├── web.xml ← Deployment Descriptor (maps URLs to Servlets) │ ├── classes/ ← Compiled .class files │ └── HelloServlet.class │ └── lib/ ← JAR files (JDBC drivers, third-party libraries) └── mysql-connector.jar
⚠ Critical Point The WEB-INF directory is NEVER served directly by the web server. A browser cannot access http://yoursite.com/WEB-INF/web.xml. This is a security feature protecting your configuration and compiled code.

web.xml — Deployment Descriptor

Tells Tomcat which class handles which URL, filter mappings, session timeout, etc.

XML — web.xml
<servlet>
    <servlet-name>Hello</servlet-name>
    <servlet-class>HelloServlet</servlet-class>
</servlet>
<servlet-mapping>
    <servlet-name>Hello</servlet-name>
    <url-pattern>/hello</url-pattern>
</servlet-mapping>
1.4 WAR File ★★☆

WAR = Web Application Archive. A single compressed file (like ZIP) containing the entire web application (HTML, JSPs, Servlets, WEB-INF, web.xml, JARs). Used to deploy web applications to a server.

📋 Asked in 2023 and 2024 Tests whether you understand the full deployment pipeline, not just writing code.

How to Create a WAR File

Shell
# Using JAR tool (run from web app root directory)
jar -cvf MyApp.war *

# Using Maven
mvn package
# Produces .war file in the target/ folder

Using IDE (Eclipse/IntelliJ): Right-click project → Export → WAR file

How to Deploy

Copy the .war file into Tomcat's webapps/ folder. Tomcat automatically extracts and deploys it. Access via http://localhost:8080/MyApp.

1.6 Session Management ★★★

HTTP is stateless — each request is independent, the server has no memory of previous requests. Session management is the technique of maintaining state across multiple requests from the same user.

Method 1 — Cookies

A cookie is a small text file stored on the client's machine by the browser.

  1. First visit: Server generates a unique session ID and sends it as a cookie in the HTTP response header.
  2. Subsequent visits: Browser automatically sends the cookie back in every request.
  3. Server reads the cookie, identifies the user.
HTTP Header
Set-Cookie: JSESSIONID=abc123; Path=/; HttpOnly

Limitation: User can disable cookies in browser.

Method 2 — Hidden Form Fields

Server embeds session data inside a hidden HTML input field.

HTML
<input type="hidden" name="sessionid" value="12345">

Limitation: Only works when user submits a form. Normal hyperlinks don't send hidden fields.

Method 3 — URL Rewriting

Session ID is appended directly to every URL.

URL
http://example.com/page.jsp;jsessionid=abc123

Advantage: Works even when cookies are disabled.

Disadvantage: Every URL must be dynamically generated. Security risk if URL is shared.

Method 4 — HttpSession Object (Java — Most Important)

Java
// Get or create a session
HttpSession session = request.getSession();

// Store data in session
session.setAttribute("username", "Alice");

// Retrieve data
String user = (String) session.getAttribute("username");

// Invalidate session (logout)
session.invalidate();

HttpSession internally uses cookies (JSESSIONID) or URL rewriting — it abstracts the mechanism from the developer.

1.8 Long Polling ★☆☆

Normal HTTP: Client sends request → Server responds immediately → Connection closes.

Long Polling: Client sends request → Server holds the connection open until it has new data → Server responds → Client immediately sends another request. This simulates real-time communication.

Details
AdvantagesSimpler than WebSockets, works with standard HTTP
DisadvantagesServer holds many open connections (resource-intensive), latency higher than WebSockets
1.9 Servlet Container / Web Container ★★☆

A Servlet Container (like Apache Tomcat) is the runtime environment for servlets. Responsibilities:

  • Lifecycle management — creating, initializing, and destroying servlet instances
  • Request routing — mapping incoming URLs to the correct servlet
  • Threading — creating a new thread for each request
  • Security — enforcing access control defined in web.xml
  • Session management — managing HttpSession objects
  • JSP compilation — converting JSP files into servlet class files

Servlets, JSP & JavaBeans

2.1 Servlet Life Cycle ★★★
📋 Appears Every Year — Very High Priority Know all three methods, their signatures, when they're called, and how many times each is called.
Servlet Class Loaded by Container ↓ init() ← Called ONCE when servlet is first loaded ↓ service() ← Called for EVERY request (spawns a new thread each time) ↙ ↘ doGet() doPost() ↓ destroy() ← Called ONCE when server shuts down / servlet unloaded ↓ Garbage Collection by JVM

init() — Called Once

Java
public void init() throws ServletException {
    // One-time initialization
    // e.g., opening DB connection, reading config
}
  • Called only once in the servlet's lifetime
  • Called when first requested OR at server startup (if load-on-startup configured)
  • Not called for subsequent user requests

service() — Called Per Request

Java
public void service(HttpServletRequest request,
                    HttpServletResponse response)
    throws ServletException, IOException {
    // Checks request type, calls doGet() or doPost()
}
  • Called for every incoming request
  • Container creates a new thread (not new servlet instance) per request
  • You generally override doGet()/doPost() not service() directly

doGet() — Handles HTTP GET

Java
public void doGet(HttpServletRequest request,
                   HttpServletResponse response)
    throws ServletException, IOException {

    response.setContentType("text/html");
    PrintWriter out = response.getWriter();
    out.println("<html><body>");
    out.println("<h1>Hello from doGet!</h1>");
    out.println("</body></html>");
}

destroy() — Cleanup

Java
public void destroy() {
    // Cleanup: close DB connections, release resources
}

load-on-startup (Asked in 2022)

Forces servlet loading at server startup, not on first request. Useful for servlets with heavy initialization.

XML — web.xml
<servlet>
    <servlet-name>MyServlet</servlet-name>
    <servlet-class>com.example.MyServlet</servlet-class>
    <load-on-startup>1</load-on-startup>  <!-- positive = load at startup -->
</servlet>

2.6 Filters ★★★

A Filter intercepts requests before they reach a servlet and/or responses before they reach the client. Think of it as a checkpoint.

Browser → Request → [Filter1] → [Filter2] → Servlet Browser ← Response ← [Filter1] ← [Filter2] ← Servlet

Uses of Filters

  • Authentication / Authorization (block unauthorized access)
  • Logging (record every request)
  • Compression
  • Input validation
  • IP-based access control (professor's favorite example!)

IP Filter — Asked in 2022 and 2024 (Write this code!)

Java — IPFilter.java
import javax.servlet.*;
import javax.servlet.http.*;

public class IPFilter implements Filter {

    public void init(FilterConfig config) throws ServletException {}

    public void doFilter(ServletRequest request,
                         ServletResponse response,
                         FilterChain chain)
        throws IOException, ServletException {

        String clientIP = request.getRemoteAddr();

        if (clientIP.equals("172.16.4.248")) {
            chain.doFilter(request, response);  // Allowed
        } else {
            HttpServletResponse res = (HttpServletResponse) response;
            res.sendError(HttpServletResponse.SC_FORBIDDEN, "Access Denied");
        }
    }

    public void destroy() {}
}
XML — Filter Registration in web.xml
<filter>
    <filter-name>IPFilter</filter-name>
    <filter-class>IPFilter</filter-class>
</filter>
<filter-mapping>
    <filter-name>IPFilter</filter-name>
    <url-pattern>/*</url-pattern>
</filter-mapping>

Count Filter (appeared in 2022)

Java
public class CountFilter implements Filter {
    private int count = 0;

    public void doFilter(ServletRequest req, ServletResponse res,
                         FilterChain chain)
        throws IOException, ServletException {
        count++;
        System.out.println("Servlet accessed " + count + " times");
        chain.doFilter(req, res);
    }

    public void init(FilterConfig c) throws ServletException {}
    public void destroy() {}
}

JDBC (Java Database Connectivity) is an API that allows Java programs to interact with relational databases using SQL, regardless of which database is used.

3.2 JDBC Connection — 5 Steps + Role of DriverManager ★★★
Java — Complete JDBC Example
import java.sql.*;

public class DBExample {
    public static void main(String[] args) throws Exception {

        // Step 1: Register the Driver
        Class.forName("com.mysql.jdbc.Driver");

        // Step 2: Create Connection
        Connection con = DriverManager.getConnection(
            "jdbc:mysql://localhost:3306/mydb",
            "root", "password"
        );

        // Step 3: Create Statement
        Statement stmt = con.createStatement();

        // Step 4: Execute Query
        ResultSet rs = stmt.executeQuery("SELECT * FROM students");
        while (rs.next()) {
            System.out.println(rs.getInt(1) + " " + rs.getString(2));
        }

        // Step 5: Close Connection
        con.close();
    }
}

Role of DriverManager (asked 2024)

  • Maintains a list of registered JDBC drivers
  • Selects the appropriate driver based on the connection URL
  • Establishes the connection via getConnection(url, user, password)
  • Checks each registered driver to see if it can handle the given URL
Connection URL Format MySQL: jdbc:mysql://localhost:3306/dbname | Oracle: jdbc:oracle:thin:@localhost:1521:xe
3.3 Statement vs PreparedStatement ★★★
📋 Asked 2022, 2023, and 2024 — Appears Every Year
AspectStatementPreparedStatement
SQL compilationCompiled every executionCompiled once, reused
PerformanceSlower for repeated queriesFaster
SQL InjectionVULNERABLEPROTECTED
ParametersConcatenated into stringUses ? placeholders
Use caseOne-time, no user inputRepeated queries, user input

When to Use PreparedStatement

  1. When query will be executed multiple times (performance)
  2. When query contains user-supplied input (security — prevents SQL injection)
  3. When working with binary data (BLOB, CLOB)
Java — Vulnerable vs Safe
// ❌ VULNERABLE — SQL Injection possible
String username = request.getParameter("user");
String query = "SELECT * FROM users WHERE username='" + username + "'";
Statement stmt = con.createStatement();
ResultSet rs = stmt.executeQuery(query);

// ✅ SAFE — PreparedStatement
PreparedStatement pstmt = con.prepareStatement(
    "SELECT * FROM users WHERE username = ?"
);
pstmt.setString(1, username);   // Parameter binding — injection impossible
ResultSet rs = pstmt.executeQuery();
3.4 Scrollable & Updatable ResultSet ★★★
📋 Asked 2022, 2023, and 2024 — Appears Every Year

By default, a ResultSet can only move forward (next()) and is read-only.

Java — Creating Scrollable + Updatable ResultSet
Statement stmt = con.createStatement(
    ResultSet.TYPE_SCROLL_SENSITIVE,    // Can scroll in both directions
    ResultSet.CONCUR_UPDATABLE          // Can update rows
);
ResultSet rs = stmt.executeQuery("SELECT * FROM emp");

ResultSet Type Constants

ConstantMeaning
TYPE_FORWARD_ONLYDefault. Only next() allowed
TYPE_SCROLL_INSENSITIVECan scroll; doesn't see DB changes after RS opened
TYPE_SCROLL_SENSITIVECan scroll; DOES see DB changes

Scrollable Navigation Methods

Java
rs.next();          // Move forward one row
rs.previous();      // Move backward one row
rs.first();         // Move to first row
rs.last();          // Move to last row
rs.absolute(5);     // Move to row 5
rs.relative(-2);   // Move 2 rows back from current

Updatable ResultSet — Merits & Demerits

Merits:

  • Can update database directly through ResultSet without separate UPDATE query
  • Code is simpler for update-while-reading scenarios
  • Can insert new rows using rs.moveToInsertRow()

Demerits:

  • Performance overhead — database must keep more metadata
  • Not all databases/drivers support it
  • Joins and aggregates typically cannot produce updatable result sets
  • Concurrency issues when multiple users access the same data
Java — Update via ResultSet
while (rs.next()) {
    if (rs.getString("dept").equals("IT")) {
        rs.updateDouble("salary", rs.getDouble("salary") * 1.1);
        rs.updateRow();  // Commit this row's changes
    }
}
3.5 Batch Processing ★★★

Collects multiple SQL statements and sends them all at once instead of one round trip per statement.

Without Batching: INSERT → DB → resp | INSERT → DB → resp | INSERT → DB → resp (3 round trips) With Batching: [INSERT + INSERT + INSERT] → DB → [resp, resp, resp] (1 round trip)
Java — Batch Processing
con.setAutoCommit(false); // Important: disable auto-commit

PreparedStatement pstmt = con.prepareStatement(
    "INSERT INTO emp VALUES (?, ?, ?)"
);

for (int i = 1; i <= 1000; i++) {
    pstmt.setInt(1, i);
    pstmt.setString(2, "Employee" + i);
    pstmt.setDouble(3, 50000.0);
    pstmt.addBatch();   // Add to batch, don't execute yet

    if (i % 100 == 0) {
        pstmt.executeBatch();   // Execute every 100 records
        con.commit();
    }
}

pstmt.executeBatch();   // Execute remaining
con.commit();
con.setAutoCommit(true);

Key Methods

  • addBatch() — adds statement to batch
  • executeBatch() — executes all batched statements, returns int[] (affected rows per statement)
  • clearBatch() — clears all batched statements
3.6 Stored Procedures ★★☆

A precompiled SQL program stored in the database. Called from Java using CallableStatement.

Java — Calling a Stored Procedure
// Assumes: CREATE PROCEDURE getEmp(IN empId INT)
CallableStatement cstmt = con.prepareCall("{call getEmp(?)}");
cstmt.setInt(1, 101);
ResultSet rs = cstmt.executeQuery();
while (rs.next()) {
    System.out.println(rs.getString("name"));
}

CGI Programming

4.1 What is CGI? ★★★

CGI = Common Gateway Interface. It is a standard (not a language, not a program — a standard interface) that defines how a web server can pass a client's request to an external program and receive the response back.

⚠ Critical Point Each CGI request spawns a new OS process. This is CGI's biggest weakness compared to Servlets (which use threads).
Client Browser | | HTTP Request ↓ Web Server | | Launches CGI program (new process!) ↓ CGI Program (runs, processes request) | | Writes output to stdout ↓ Web Server reads stdout | | Sends output as HTTP Response ↓ Client Browser
4.2 Principles of CGI Architecture ★★☆
  1. CGI is a specification, not a language
  2. The web server identifies a CGI request by URL (e.g., /cgi-bin/script.pl)
  3. Server sets environment variables with request information
  4. Server launches the CGI program as a separate OS process
  5. CGI program reads data from environment variables (GET) or stdin (POST)
  6. CGI program writes its output (headers + body) to stdout
  7. Server reads stdout and sends it as the HTTP response to the client
4.3 How Web Server Identifies a CGI Request ★★☆

Two ways:

  1. Special directory: URL path includes a designated CGI directory (conventionally /cgi-bin/). Any executable file in this directory is treated as CGI.
  2. File extension: Server configured to treat certain extensions (.cgi, .pl) as CGI scripts.
URL Examples
http://example.com/cgi-bin/hello.pl   # CGI — in cgi-bin directory
http://example.com/index.html          # Static — not CGI

4.7 CGI Languages & Examples ★★★

Languages Used for CGI (asked 2022, 2023)

Perl, Python, Bash/Shell, C/C++, Ruby — CGI is language-agnostic. Java is rarely used for CGI (Servlets are preferred).

Hello World in Python CGI (asked 2022, 2023)

Python — hello.py
#!/usr/bin/python

print("Content-type: text/html")  # Header
print("")                           # Blank line (MANDATORY)

Deployment procedure:

  1. Place in server's cgi-bin directory: /var/www/cgi-bin/hello.py
  2. Make executable: chmod +x hello.py
  3. Ensure shebang line (#!/usr/bin/python) is correct
  4. Access via: http://localhost/cgi-bin/hello.py

Web Services, SOA & Cloud

5.1 Web Services Overview ★★★

A Web Service is a software system that provides functionality over a network using standard internet protocols, enabling applications on different platforms to communicate.

Advantages of Web Services (asked 2022, 2023, 2024)

  • Interoperability — different platforms and languages can communicate
  • Reusability — a service written once can be used by any client
  • Loose coupling — client and server can evolve independently
  • Standardized communication — uses HTTP and XML, universally supported
  • Firewall-friendly — uses HTTP port 80/443, rarely blocked
  • Cost reduction — reuse existing services instead of building from scratch
5.2 XML-RPC ★★★

XML-RPC = XML Remote Procedure Call. Allows a program to execute a function on a remote machine over HTTP using XML.

Operational Principle

  1. Client encodes the procedure name and parameters in XML
  2. Sends via HTTP POST to the server
  3. Server decodes XML, executes the function
  4. Server encodes the result in XML
  5. Sends XML response back via HTTP

XML-RPC Request Format (asked 2022, 2023)

XML — Request
<?xml version="1.0"?>
<methodCall>
    <methodName>calculator.add</methodName>
    <params>
        <param>
            <value><int>2</int></value>
        </param>
        <param>
            <value><int>3</int></value>
        </param>
    </params>
</methodCall>
XML — Response
<?xml version="1.0"?>
<methodResponse>
    <params>
        <param>
            <value><int>5</int></value>
        </param>
    </params>
</methodResponse>
5.3 SOAP ★★★

SOAP = Simple Object Access Protocol. XML-based messaging protocol for exchanging structured information in web services. More powerful than XML-RPC.

SOAP Message Structure

Mnemonic: Envelope → Header → Body The professor's 2023 paper had "SOAP first → env? body" written on it — he wants you to know the structure sequence.
XML — SOAP Structure
<soap:Envelope                          <!-- MANDATORY: wraps everything -->
    xmlns:soap="http://schemas.xmlsoap.org/soap/envelope/">

    <soap:Header>                       <!-- OPTIONAL: auth, routing info -->
        <auth:token>abc123</auth:token>
    </soap:Header>

    <soap:Body>                         <!-- MANDATORY: actual message -->
        <m:addRequest xmlns:m="http://calculator.example.com">
            <a>2</a>
            <b>3</b>
        </m:addRequest>
    </soap:Body>

</soap:Envelope>

SOAP for Calculator.add(2,3) — Asked 2022 and 2024

XML — SOAP Request
<?xml version="1.0"?>
<soap:Envelope xmlns:soap="http://schemas.xmlsoap.org/soap/envelope/"
               xmlns:calc="http://calculator.example.com">
    <soap:Body>
        <calc:add>
            <calc:a>2</calc:a>
            <calc:b>3</calc:b>
        </calc:add>
    </soap:Body>
</soap:Envelope>
XML — SOAP Response
<?xml version="1.0"?>
<soap:Envelope xmlns:soap="http://schemas.xmlsoap.org/soap/envelope/"
               xmlns:calc="http://calculator.example.com">
    <soap:Body>
        <calc:addResponse>
            <calc:result>5</calc:result>
        </calc:addResponse>
    </soap:Body>
</soap:Envelope>
5.4 WSDL ★★★

WSDL = Web Services Description Language. An XML document that describes a web service — what operations it offers, what parameters they take, and where the service is located.

📋 Asked 2022, 2023, and 2024 — Appears Every Year

How WSDL Helps Invoke a Web Service

WSDL tells the client:

  • What operations are available — e.g., add, subtract, multiply
  • What parameters each operation takes and their types
  • What each operation returns
  • Where the service is located — the URL endpoint
  • How to communicate — SOAP over HTTP, or HTTP GET/POST
Model Answer (write exactly this) A WSDL document acts as a contract between the web service provider and consumer. It describes the service interface (methods, parameters, return types) and the endpoint (URL). A client reads the WSDL and generates stub code to call the service, without knowing the internal implementation.

5.6 Microservices Architecture ★★☆

An application is broken into many small, independent services, each responsible for one specific function, each deployable independently.

ProsCons
Independent deployment — update one without touching othersComplexity — managing many services is hard
Technology flexibility — different languages/databases per serviceNetwork overhead — services communicate over network, adds latency
Fault isolation — failure of one service doesn't crash the whole appData consistency — each service has its own DB; consistency is hard
Targeted scalability — scale only the services that need itTesting — integration testing is complex
Smaller codebases — easier to understand and maintainOperational overhead — need DevOps expertise, Kubernetes etc.
5.7 MVC Architecture ★★☆

MVC = Model-View-Controller — a design pattern that separates application concerns.

User → Controller (Servlet) → Model (JavaBean / DB logic) → View (JSP) User ←─────────── View renders and returns result ─────────────────────
  • Model — Business logic and data (JavaBeans, JDBC code)
  • View — Presentation layer (JSP pages)
  • Controller — Request handling and routing (Servlets)

Advantages of MVC

  • Separation of concerns — UI changes don't affect business logic
  • Easier to maintain and test each component independently
  • Multiple views can use the same model
  • Team members can work on different layers simultaneously
