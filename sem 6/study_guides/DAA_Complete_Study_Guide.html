T Time & Space Complexity

HIGH FREQ
Core Concept

Time complexity measures how many basic operations an algorithm performs as input size n grows. Space complexity measures how much memory it uses. We care about the rate of growth, not exact counts — because a constant doesn't matter for large n.

When we say an algorithm is O(n²), we mean: double the input → roughly 4× more work. This is the key insight.

How to Count Operations

The professor frequently gives code snippets and asks for running time. Three methods:

  • Count iterations: Count how many times the loop body executes
  • Count basic operations: Pick one key operation (comparison, assignment) and count it
  • Use recurrence: For recursive algorithms, write T(n) = ... and solve
// Example from 2024 paper — Function A void Function(int n) { int i = 1, s = 1; while(s < n) { // s grows as: 1,1+1=2,2+2=4,4+3=7... i++; // s = 1+2+3+...+i = i(i+1)/2 s = s + i; // s < n means i(i+1)/2 < n print("*"); // So i ~ √(2n), runs O(√n) times } } // Function B from 2024 paper for(i = n/2; i <= n; i++) // runs n/2 times → O(n) for(j = 1; j + n/2 <= n; j++) // runs n/2 times → O(n) for(k = 1; k <= n; k = k*2) // k doubles → O(log n) count++; // Total: O(n × n × log n) = O(n² log n)
📌 Professor's Pattern: He consistently gives 2-3 code snippets and asks "What is the running time?" Write the dominant term only (no constants). Show your reasoning step by step — loops × loops × etc.

Ω Asymptotic Notations: O, Ω, Θ, o

HIGH FREQ
Core Concept

These are formal tools to describe growth rates without getting bogged down in machine-specific constants.

NotationMeaningThink of it asDefinition
O(g(n)) Upper bound "At most" / worst-case ceiling ∃ c, n₀ such that f(n) ≤ c·g(n) for all n ≥ n₀
Ω(g(n)) Lower bound "At least" / best-case floor ∃ c, n₀ such that f(n) ≥ c·g(n) for all n ≥ n₀
Θ(g(n)) Tight bound "Exactly" — sandwiched Both O and Ω: c₁·g(n) ≤ f(n) ≤ c₂·g(n)
o(g(n)) Strict upper bound Strictly smaller, not equal lim(n→∞) f(n)/g(n) = 0
Key Insight: O gives us a guarantee that the algorithm won't be worse than this. Θ is the strongest statement — it says the algorithm is exactly this tight. When asked for "tight bound," always give Θ if possible.
Common Growth Rates (slowest to fastest)
O(1) < O(log n) < O(√n) < O(n) < O(n log n) < O(n²) < O(n³) < O(2ⁿ) < O(n!)
📌 Exam Trick: For f(n) = 3n² + 5n + 2, the tight bound is Θ(n²). Drop all lower order terms and constants for asymptotic notation.

R Recurrence Relations & Master Theorem

HIGH FREQ — Every Paper
Core Concept

When an algorithm calls itself recursively, we express its runtime as T(n) = aT(n/b) + f(n). Solving this tells us the total runtime.

The Master Theorem is the fastest way to solve divide-and-conquer recurrences of the form T(n) = aT(n/b) + n^k:

Master Theorem — T(n) = aT(n/b) + nᵏ
Case 1: a > bᵏ → T(n) = Θ(n^(log_b a)) Case 2: a = bᵏ → T(n) = Θ(nᵏ log n) Case 3: a < bᵏ → T(n) = Θ(nᵏ)
Solving the 2025 Paper Questions Step by Step

Q: T(n) = 3T(n/2) + n²

a = 3, b = 2, f(n) = n² → k = 2 Compare: a vs bᵏ → 3 vs 2² = 4 Since a(3) < bᵏ(4) → Case 3 ∴ T(n) = Θ(n²)

Q: T(n) = 8T(n/2) + n log n

a = 8, b = 2, f(n) = n log n → k ≈ 1 (dominant term is n¹) Compare: a vs bᵏ → 8 vs 2¹ = 2 Since a(8) > bᵏ(2) → Case 1 log_b(a) = log₂(8) = 3 ∴ T(n) = Θ(n³)

Q: T(n) = 2T(n/2) + √n

a = 2, b = 2, f(n) = n^(1/2) → k = 1/2 Compare: a vs bᵏ → 2 vs 2^(0.5) ≈ 1.41 Since a(2) > bᵏ(1.41) → Case 1 log₂(2) = 1 ∴ T(n) = Θ(n)

Q: T(n) = 3T(n/2) + n

a = 3, b = 2, k = 1 bᵏ = 2¹ = 2 a(3) > bᵏ(2) → Case 1 log₂(3) ≈ 1.585 ∴ T(n) = Θ(n^1.585)

Q: T(n) = √2 · T(n/2) + log n

a = √2 = 2^(0.5), b = 2, f(n) = log n → k = 0 (n⁰ = 1, log n grows slower) bᵏ = 2⁰ = 1 a(√2 ≈ 1.41) > bᵏ(1) → Case 1 log₂(√2) = log₂(2^0.5) = 0.5 ∴ T(n) = Θ(n^0.5) = Θ(√n)
📌 Professor's Style: He gives 2–3 recurrences every single year (CO1b). Always show: write a, b, k → compute bᵏ → compare with a → state which case → write the answer. Never skip steps.

H Heaps — Min/Max Heap, Leaf Nodes, kth Element

HIGH FREQ — CO1a every year
Core Concept

A heap is a complete binary tree stored as an array, satisfying the heap property:

  • Min-Heap: Every parent ≤ its children. Root = minimum element.
  • Max-Heap: Every parent ≥ its children. Root = maximum element.

For an array of n elements: index 1 is the root. Left child of i = 2i. Right child of i = 2i+1. Parent of i = ⌊i/2⌋.

Leaf Nodes in a Heap of n Elements

In a complete binary tree with n nodes:

Leaf Node Formula
Leaf nodes occupy indices from ⌊n/2⌋ + 1 to n Number of leaf nodes = n - ⌊n/2⌋ = ⌈n/2⌉ Example: n = 7 → leaves at indices 4,5,6,7 → 4 leaves Example: n = 10 → leaves at indices 6,7,8,9,10 → 5 leaves
Algorithm: Count Leaf Nodes in Min-Heap
CountLeaves(Heap A, int n): return n - floor(n/2) // Time complexity: O(1) // No traversal needed — it's a mathematical property!
Algorithm: Find kth Minimum from Min-Heap

The professor asked: 4th minimum (2024) and 16th largest from 60 numbers (2025 — which means 45th smallest from 60).

Method: Use an auxiliary min-heap. Extract-min k times.

FindKthMinimum(MinHeap H, int k): Create auxiliary min-heap AH Insert (H[1], index=1) into AH // root = minimum for i = 1 to k-1: (val, idx) = ExtractMin(AH) // remove current min if 2*idx ≤ n: // has left child Insert(AH, H[2*idx], 2*idx) if 2*idx+1 ≤ n: // has right child Insert(AH, H[2*idx+1], 2*idx+1) return ExtractMin(AH).val // kth minimum // Time Complexity: O(k log k) // Space Complexity: O(k)
Why this works: The kth minimum can only be found among the k-1 smallest elements. Each time we remove the current minimum, its children become candidates. The auxiliary heap tracks these candidates. Size of auxiliary heap never exceeds 2k, so each operation is O(log k).
2025: Find 16th Largest from 60 Numbers

16th largest = 45th smallest (from a set of 60). But building a max-heap and extracting 16 times is more direct:

Find16thLargest(array A[1..60]): BuildMaxHeap(A) // O(n) = O(60) = O(1) constant for i = 1 to 15: ExtractMax(A) // each O(log n) return A[1] // now root = 16th largest // Total: O(n + k log n) where n=60, k=16 // Since n is fixed: O(60 + 16·log 60) = O(constant) ≈ O(1) // General: O(n + k log n)
📌 Professor asks every year: Give the algorithm + prove it + compute time AND space complexity. Never give just code without proving correctness.

A Amortized Analysis

MED FREQ — CO2b 2025
Core Concept

Amortized analysis gives the average cost per operation over a sequence of operations, even if some individual operations are expensive. The key point: occasional expensive operations are "paid for" by many cheap ones.

Think of it like a phone bill: some months are expensive (you buy a new phone), but amortized over 24 months, the monthly cost is reasonable.

Classic Example: Dynamic Array (ArrayList)

Start with array of size 1. When full, double the size (copying all elements). Cost of doubling: O(n). But this happens rarely.

Amortized Cost Analysis
Insertions: 1, 1, 1, 2, 1, 1, 1, 4, 1, 1, 1, 1, 1, 1, 1, 8, ... (Doubling costs: 1, 2, 4, 8, 16, ... — happens at powers of 2) Total cost for n insertions = n + (1+2+4+...+n) = n + 2n - 1 ≈ 3n Amortized cost per insertion = 3n/n = O(1)

So even though some insertions cost O(n), the amortized cost per insertion is O(1).

📌 How to answer: Define amortized analysis → give the dynamic array example → calculate total cost → divide by n → show amortized = O(1). 5 marks = about 10-12 sentences.

≈ Best Case vs Worst Case — When They're Same

CO2a — 2025 Paper
Core Concept

Best case: Input arrangement that causes fewest operations. Worst case: Input that causes most operations. When they're equal, the algorithm is Θ (tight bound).

When Best = Worst Case (with examples)

1. Linear Search for all elements: If you search every element to build a list, you always do n comparisons regardless of order → Θ(n).

2. Merge Sort: Always divides and merges the same way — no early exit. Best = Worst = Θ(n log n) regardless of input.

3. Matrix Multiplication: Always does n³ multiplications regardless of values.

4. Heap Sort: Even on a sorted array, heapsort still takes Θ(n log n) — the process doesn't short-circuit.

Comparison with Algorithms Where They Differ
AlgorithmBest CaseWorst CaseSame?
Linear SearchO(1) — found at startO(n) — not foundNo
Binary SearchO(1) — found at midO(log n)No
Insertion SortO(n) — already sortedO(n²) — reverse sortedNo
Merge SortΘ(n log n)Θ(n log n)YES
Heap SortΘ(n log n)Θ(n log n)YES

∪ Disjoint Sets / Union-Find with Path Compression

CO3d — 2025 Paper OR option
Core Concept

Disjoint Sets (Union-Find) is a data structure that maintains a collection of disjoint sets, supporting two operations: Find (which set does element x belong to?) and Union (merge two sets).

Used in: Kruskal's MST, cycle detection, network connectivity problems.

Path Compression — The Key Optimization

Naively, Find(x) walks up the parent chain to the root: O(n) in worst case (chain-like tree). Path compression flattens this: after finding the root, make every node on the path point directly to the root.

Find(x): Union(x, y): if parent[x] ≠ x: rx = Find(x) parent[x] = Find(parent[x]) ry = Find(y) // path compression here! if rx ≠ ry: return parent[x] if rank[rx] < rank[ry]: parent[rx] = ry // union by rank else if rank[rx] > rank[ry]: parent[ry] = rx else: parent[ry] = rx rank[rx]++
Why Path Compression Matters: Before compression, Find could be O(n). After compression, the tree becomes flat. With union by rank + path compression, amortized cost per operation is nearly O(1) — technically O(α(n)) where α is the inverse Ackermann function (grows so slowly it's practically constant for all practical inputs).
Example with Path Compression

Suppose we have a chain: 1←2←3←4←5 (5 is root). Find(1) normally walks: 1→2→3→4→5. With path compression, after Find(1) returns 5, all nodes 1,2,3,4 now point directly to 5. Next call to Find(1) or Find(2) costs O(1).

📌 For 8-mark answer: Explain the problem → show naive find (chain, O(n)) → show path compression with code → draw before/after tree diagram → state amortized complexity O(α(n)) ≈ O(1).

÷ Divide and Conquer Paradigm

HIGH FREQ
Core Concept

Three steps: Divide the problem into subproblems → Conquer each recursively → Combine solutions. Works best when subproblems are independent and of equal size.

The power of D&C: splitting n into n/2 and n/2 gives log n levels → O(n log n) is often achievable.

Min & Max in a Set — D&C Approach (2024 paper)
MinMax(A, low, high): if low == high: // 1 element return (A[low], A[low]) if high == low + 1: // 2 elements return (min(A[low],A[high]), max(A[low],A[high])) mid = (low + high) / 2 (lmin, lmax) = MinMax(A, low, mid) (rmin, rmax) = MinMax(A, mid+1, high) return (min(lmin, rmin), max(lmax, rmax)) // Recurrence: T(n) = 2T(n/2) + 2 // Comparisons: (3n/2 - 2) — better than naïve 2n-2 // Time: O(n), Space: O(log n) recursion stack
D&C vs Dynamic Programming vs Greedy
ParadigmSubproblemsOverlap?Local optimal = Global?Examples
Divide & ConquerIndependentNoN/AMergesort, Binary Search, Quicksort
Dynamic ProgrammingOverlappingYes — memoizedNoLCS, Fibonacci, Knapsack 0/1
GreedyOne at a timeNoYes (proven)Fractional Knapsack, Huffman, Kruskal
📌 Prof's Question: "Is greedy always optimal? Justify with example." Answer: NO. Counterexample: 0/1 Knapsack — greedy by ratio fails. But YES for fractional knapsack and Huffman. The key is whether the "greedy choice property" and "optimal substructure" both hold.

DP Dynamic Programming

HIGH FREQ — Fibonacci, LCS, Edit Distance
Core Concept

DP solves problems by breaking them into overlapping subproblems and storing results (memoization/tabulation) to avoid recomputation. Two properties needed: Optimal Substructure (optimal solution contains optimal solutions of subproblems) and Overlapping Subproblems (same subproblems solved multiple times).

Fibonacci via DP (2025 paper OR option)
// Naïve recursion: T(n) = T(n-1) + T(n-2) + 1 → O(2ⁿ) ← exponential! FibDP(n): F[0] = 0, F[1] = 1 for i = 2 to n: F[i] = F[i-1] + F[i-2] // reuse stored values return F[n] // Time: O(n), Space: O(n) — or O(1) if you only keep last 2 // DP advantage: eliminates redundant recomputation
LCS (Longest Common Subsequence) — 2023 Paper

Given strings A = "xzyzzyx" and B = "zxyyzxz", find LCS.

LCS(A[1..m], B[1..n]): // L[i][j] = LCS length of A[1..i] and B[1..j] for i = 0 to m: L[i][0] = 0 for j = 0 to n: L[0][j] = 0 for i = 1 to m: for j = 1 to n: if A[i] == B[j]: L[i][j] = L[i-1][j-1] + 1 else: L[i][j] = max(L[i-1][j], L[i][j-1]) return L[m][n] // Time: O(mn), Space: O(mn)

For A="xzyzzyx", B="zxyyzxz": fill the table row by row. LCS length = 4 (one answer: "zyzy" or "zyzx").

String Edit Distance — 2024 Paper (JADAVPUR vs JALPAIGURI)
EditDistance(X, Y): // D[i][j] = edit distance of X[1..i] and Y[1..j] D[i][0] = i (i deletions) D[0][j] = j (j insertions) for i = 1 to |X|: for j = 1 to |Y|: if X[i] == Y[j]: cost = 0 else: cost = 1 D[i][j] = min(D[i-1][j] + 1, // deletion D[i][j-1] + 1, // insertion D[i-1][j-1] + cost) // substitution
📌 Professor expects: Write the recurrence → fill the DP table (show all values) → trace back to get the actual sequence → state time/space complexity.

S String Matching (Naïve / KMP)

CO3b — 2025 Paper
Core Concept

Given text L and pattern P, find all occurrences of P in L. The 2025 paper gives L = "aabbaabbababa" and asks to find pattern "baba".

Naïve String Matching
NaiveSearch(L, P): n = len(L), m = len(P) for i = 0 to n-m: match = true for j = 0 to m-1: if L[i+j] ≠ P[j]: match = false; break if match: print "Found at", i // Time: O((n-m+1)·m) ≈ O(nm) worst case

For L="aabbaabbababa", P="baba" (m=4, n=13):

Check starting positions 0 through 9. At i=7: L[7..10]="baba" → MATCH. At i=9: L[9..12]="baba" → MATCH. Found at positions 7 and 9.

KMP — Efficient String Matching

KMP avoids redundant comparisons by precomputing a failure function (prefix function). When a mismatch occurs, instead of restarting from scratch, we jump using the failure function.

Complexity Comparison
Naïve: O(nm) — can be slow for large texts KMP: O(n + m) — linear time! Preprocessing: O(m) to build failure function

G Greedy Algorithms

Every Paper
Core Concept

A greedy algorithm makes the locally optimal choice at each step, hoping to reach a globally optimal solution. It works when: (1) Greedy Choice Property holds (local optimal → global optimal) AND (2) Optimal Substructure holds.

Fractional Knapsack — 2023/2024 Paper

m=16, n=6, P=(2,6,8,1,3,5), W=(10,6,5,3,1,3)

// Step 1: Compute profit/weight ratio for each item Item: 1 2 3 4 5 6 P: 2 6 8 1 3 5 W: 10 6 5 3 1 3 P/W: 0.2 1.0 1.6 0.33 3.0 1.67 // Step 2: Sort by ratio descending Order: 5(3.0), 6(1.67), 3(1.6), 2(1.0), 4(0.33), 1(0.2) // Step 3: Fill knapsack greedily Item 5: W=1 <= 16, take all → profit=3, remaining=15 Item 6: W=3 <= 15, take all → profit=5, remaining=12 Item 3: W=5 <= 12, take all → profit=8, remaining=7 Item 2: W=6 <= 7, take all → profit=6, remaining=1 Item 4: W=3 > 1, take 1/3 → profit=1/3, remaining=0 Total profit = 3+5+8+6+1/3 = 22.33

Hf Huffman Coding

CO3e — 2025 Paper, 2024 Paper
Core Concept

Huffman coding builds an optimal prefix-free binary code — frequent characters get shorter codes. It's a greedy algorithm: always merge the two nodes with the smallest frequencies first.

Algorithm
  • 1Create a leaf node for each character with its frequency. Insert all in a min-priority queue.
  • 2While queue has more than one node: extract the two minimum-frequency nodes (x and y). Create a new internal node with frequency = freq(x) + freq(y). Make x left child, y right child. Insert back into queue.
  • 3The remaining node is the root. Assign 0 to left edges, 1 to right edges. Read codes from root to each leaf.
Time Complexity
Building initial heap: O(n) n-1 merge operations, each O(log n) Total: O(n log n)
2025 Paper: Characters A,B,C,D,E with probabilities 0.5, 0.35, 0.5, 0.1, 0.4 (and 0.2 for '-')

Note: The second row in the 2025 paper shows a different set of probabilities (0.5, 0.04, 0.02, 0.02, 0.4, 0.01). Let me solve the second row (more typical Huffman exam values):

Characters: A=0.5, B=0.04, C=0.02, D=0.02, E=0.4, -=0.01 Step 1: Min-heap (sorted): - (0.01), C(0.02), D(0.02), B(0.04), E(0.4), A(0.5) Merge 1: -(0.01) + C(0.02) = node1(0.03) Queue: D(0.02), node1(0.03), B(0.04), E(0.4), A(0.5) Merge 2: D(0.02) + node1(0.03) = node2(0.05) Queue: B(0.04), node2(0.05), E(0.4), A(0.5) Merge 3: B(0.04) + node2(0.05) = node3(0.09) Queue: node3(0.09), E(0.4), A(0.5) Merge 4: node3(0.09) + E(0.4) = node4(0.49) Queue: A(0.5), node4(0.49) Merge 5: A(0.5) + node4(0.49) = ROOT(0.99) Codes: A=0, E=10, B=110, D=1110, C=11110, -=11111

Verify optimality: Total bits = 0.5×1 + 0.4×2 + 0.04×3 + 0.02×4 + 0.02×5 + 0.01×5 = 0.5+0.8+0.12+0.08+0.1+0.05 = 1.65 bits/character

K 0/1 Knapsack (DP) — 2025 Paper

CO3e — 2025 Paper
Core Concept

Given items with weights and profits, and capacity W, maximize profit. In 0/1 knapsack, each item is either taken (1) or not (0) — no fractions. Greedy fails here; DP is needed.

2025 Paper: W=60, Items A(p=281,w=40), B(p=101,w=10), C(p=121,w=20), D(p=121,w=24)
// dp[i][w] = max profit using items 1..i with capacity w dp[0][w] = 0 for all w dp[i][w] = dp[i-1][w] if w[i] > w dp[i][w] = max(dp[i-1][w], if w[i] ≤ w dp[i-1][w-w[i]] + p[i]) Items: A(281,40), B(101,10), C(121,20), D(121,24) Key evaluations at W=60: Take A+B: 281+101=382, weight=50 ≤ 60 ✓ Take A+C: 281+121=402, weight=60 ≤ 60 ✓ Take A+D: 281+121=402, weight=64 > 60 ✗ Take B+C+D: 101+121+121=343, weight=54 ≤ 60 ✓ Take A+B+... : 281+101=382, remaining=10, nothing fits Best: A+C = 402 profit, weight = 60 (exactly fits!) // Time: O(nW) = O(4×60) = O(240) // Space: O(nW) — can reduce to O(W)

♛ Backtracking — N-Queens Problem

CO3d — 2025 (5-queen), 2023/2024 (4-queen)
Core Concept

Backtracking builds a solution step by step, abandoning a path ("backtracking") as soon as it determines the path cannot lead to a valid solution. It's smarter than brute force.

N-Queens: Place N queens on an N×N board so no two queens attack each other (no same row, column, or diagonal).

4-Queens — All Solutions
Place queens row by row. For each row, try columns 1-4. Check: no conflict in same column, or diagonals |row-i| = |col-col[i]| Solution 1: Q at (1,2), (2,4), (3,1), (4,3) Board: . Q . . . . . Q Q . . . . . Q . Solution 2: Q at (1,3), (2,1), (3,4), (4,2) Board: . . Q . Q . . . . . . Q . Q . .
5-Queens — Key Solutions

5-Queens has 10 fundamental solutions. Some valid placements:

Solution 1: (1,1), (2,3), (3,5), (4,2), (5,4) Solution 2: (1,1), (2,4), (3,2), (4,5), (5,3) Solution 3: (1,2), (2,4), (3,1), (4,3), (5,5)
Backtracking Algorithm
NQueens(row, n, col[]): if row > n: print solution; return for c = 1 to n: if isSafe(row, c, col): col[row] = c NQueens(row+1, n, col) col[row] = 0 // backtrack isSafe(row, c, col): for i = 1 to row-1: if col[i]==c or |col[i]-c|==|i-row|: return false return true
Complexity
Worst case: O(n!) — try all permutations With pruning: much better in practice 4-Queens: 2 solutions out of 4! = 24 attempts

Δ Maximum Difference Between Any Two Elements in O(n)

CO3b OR — 2025, 2024 Papers
Problem Statement

Given an array of n numbers (not necessarily distinct), find the maximum difference between any two elements in O(n) time.

Note: The maximum difference is simply max_element − min_element.

MaxDifference(A[1..n]): min_val = A[1] max_val = A[1] for i = 2 to n: if A[i] < min_val: min_val = A[i] if A[i] > max_val: max_val = A[i] return max_val - min_val // Time: O(n) — single pass // Space: O(1) // Comparisons: exactly 2(n-1)
Why O(n) is optimal: We must look at every element at least once (otherwise we might miss the max or min), so Ω(n) is a lower bound. Our algorithm achieves this, making it optimal.

↕ Sorting Algorithms — Stable Sort, Insertion Sort

CO4a — Every Paper
Stable Sort

A sort is stable if elements with equal keys appear in the same relative order in the output as in the input. Insertion Sort, Merge Sort are stable. Heap Sort and Quicksort are NOT stable.

⊕ Merging Multiple Sorted Lists

CO4c — 2025 Paper
Problem: Lists L1(asc), L2(desc), L3(asc), L4(desc) → All Descending

Given four lists of sizes k1, k2, k3, k4 in alternating orders, produce a single descending list.

Algorithm
  • 1Reverse L1 and L3 (they're ascending → make descending). Cost: O(k1) + O(k3)
  • 2Now all 4 lists are in descending order.
  • 3Use a min-heap of size 4. Insert the first element from each list with its list index.
  • 4Extract-max repeatedly (use max-heap): extract, add to result, insert next element from same list.
  • 5Repeat until all lists exhausted.
Complexity
n = k1+k2+k3+k4 (total elements) Reversals: O(k1+k3) = O(n) Heap operations: n extractions × O(log 4) = O(n) Total: O(n log k) where k=4 → O(n)

D Dijkstra's Algorithm & Negative Weights

CO5a — 2025 Paper (Can you apply it? Justify)
Core Concept

Dijkstra's finds shortest paths from a source to all vertices in a weighted graph. It's a greedy algorithm: always processes the unvisited vertex with the current shortest distance.

2025 Paper: "Can you apply Dijkstra's to this graph? Justify."

The 2025 graph has a negative edge weight (−3 and −4). The answer is: NO, you cannot reliably apply Dijkstra's to this graph.

📌 Why Dijkstra fails with negative edges: Dijkstra's greedy assumption is "once a node is finalized, its distance is correct." With negative edges, a path going through a later node with a negative edge might give a shorter path to an already-finalized node. This invalidates the greedy choice. Use Bellman-Ford instead for graphs with negative weights (but no negative cycles).
Dijkstra's Algorithm
Dijkstra(G, source s): dist[s] = 0; dist[v] = ∞ for all v ≠ s PQ = min-priority queue with all vertices, keyed by dist while PQ not empty: u = ExtractMin(PQ) // closest unvisited vertex for each neighbor v of u: if dist[u] + w(u,v) < dist[v]: dist[v] = dist[u] + w(u,v) DecreaseKey(PQ, v) // update priority // Time: O((V+E) log V) with binary heap // Works ONLY for non-negative edge weights

− Detecting Negative Cycles — Bellman-Ford

CO5b — 2025 Paper
How to Detect a Negative Cycle

Run Bellman-Ford. It relaxes all edges V-1 times. After V-1 iterations, do ONE MORE iteration — if any distance can still be reduced, there is a negative cycle.

BellmanFord(G, s): dist[s]=0; dist[v]=∞ for v≠s for i = 1 to V-1: for each edge (u,v,w): if dist[u]+w < dist[v]: dist[v] = dist[u]+w // Negative cycle detection: for each edge (u,v,w): if dist[u]+w < dist[v]: print "Negative cycle exists!" return false // Time: O(VE) — slower than Dijkstra but handles neg. weights
Why V-1 iterations? The shortest path (without negative cycles) can have at most V-1 edges. So V-1 relaxations suffice for true shortest paths. If the V-th iteration still improves a distance, that improvement is only possible through a cycle that keeps getting shorter — a negative cycle.

🌲 Minimum Spanning Tree — Kruskal's & Prim's

CO5 OR — 2025, 2024, 2023 Papers
Core Concept

A Minimum Spanning Tree of a connected weighted graph is a subset of edges that connects all vertices with minimum total weight, using exactly V-1 edges.

Kruskal's Algorithm (Edge-based, Greedy)
  • 1Sort all edges by weight in ascending order.
  • 2Use Union-Find to track components.
  • 3For each edge (u,v) in sorted order: if Find(u) ≠ Find(v) (no cycle), add edge to MST and Union(u,v).
  • 4Stop when MST has V-1 edges.
Kruskal's Complexity
Sorting edges: O(E log E) = O(E log V) Union-Find operations: O(E α(V)) ≈ O(E) Total: O(E log V)

Prim's Algorithm (Vertex-based, Greedy)
  • 1Start with any vertex. Mark it as in MST.
  • 2Of all edges connecting MST to non-MST vertices, pick the minimum weight edge.
  • 3Add that vertex and edge to MST.
  • 4Repeat until all V vertices are in MST.
Prim's Complexity
With binary heap: O(E log V) With Fibonacci heap: O(E + V log V) Better than Kruskal for dense graphs (E ≈ V²)

P P, NP, NP-Complete, NP-Hard

CO6 — Every Paper
The Four Classes
ClassDefinitionExamples
P Problems solvable in polynomial time O(nᵏ) by a deterministic algorithm Sorting, Binary Search, MST, Shortest Path
NP Problems where a given solution can be verified in polynomial time. (May not be solvable in poly time) Satisfiability, Hamiltonian Path, Graph Coloring
NP-Complete Problems that are in NP AND every NP problem reduces to it in polynomial time. "Hardest in NP." SAT, 3-SAT, Graph Coloring, 0/1 Knapsack, Clique
NP-Hard At least as hard as NP-Complete, but may not be in NP (no poly verifier). Could be harder than NP. Halting Problem, Optimization versions of NP-C
The P vs NP Question: Is P = NP? Nobody knows — it's the greatest open problem in computer science. If P = NP, all NP problems would be efficiently solvable. Most believe P ≠ NP.
How to Prove NP-Completeness

To prove problem X is NP-Complete:

  • 1Show X ∈ NP: Given a solution, can you verify it in polynomial time? Yes → X is in NP.
  • 2Show X is NP-Hard: Take a known NP-Complete problem Y. Show Y ≤ₚ X (Y reduces to X in poly time). If you can solve X, you can solve Y → X is at least as hard as Y.

∧ Prove 3-SAT is NP-Complete

CO6 — 2025 Paper (10 marks)
What is 3-SAT?

A Boolean formula in Conjunctive Normal Form (CNF) with exactly 3 literals per clause. Given such a formula, is there an assignment of true/false to variables that satisfies ALL clauses?

Example: (x₁ ∨ x₂) ∧ (x̄₁ ∧ x̄₂) ∧ (x₁ ∨ x₃) — this appears in the 2023 paper notes.

Proof: 3-SAT is NP-Complete

Part 1: 3-SAT ∈ NP

Given an assignment of variables, we can verify in O(n) time whether all clauses are satisfied. For each clause, check if at least one literal is true. This is polynomial → 3-SAT ∈ NP.

Part 2: 3-SAT is NP-Hard (reduce SAT → 3-SAT)

We know SAT (general boolean satisfiability) is NP-Complete (by Cook's theorem — first NP-Complete problem). We show SAT ≤ₚ 3-SAT:

  • Take any clause in SAT with k literals.
  • If k = 1: (l₁) → expand to (l₁ ∨ y₁ ∨ y₂) ∧ (l₁ ∨ y₁ ∨ ȳ₂) ∧ (l₁ ∨ ȳ₁ ∨ y₂) ∧ (l₁ ∨ ȳ₁ ∨ ȳ₂) using fresh variables y₁, y₂.
  • If k = 2: (l₁ ∨ l₂) → (l₁ ∨ l₂ ∨ y) ∧ (l₁ ∨ l₂ ∨ ȳ) using fresh variable y.
  • If k = 3: already in correct form.
  • If k > 3: (l₁ ∨ ... ∨ lₖ) → (l₁ ∨ l₂ ∨ y₁) ∧ (ȳ₁ ∨ l₃ ∨ y₂) ∧ ... ∧ (ȳₖ₋₃ ∨ lₖ₋₁ ∨ lₖ)

This transformation is polynomial (O(n) new clauses and variables). The original SAT formula is satisfiable if and only if the 3-CNF formula is satisfiable. Therefore SAT ≤ₚ 3-SAT, making 3-SAT NP-Hard.

Since 3-SAT ∈ NP and 3-SAT is NP-Hard → 3-SAT is NP-Complete. □

🎨 Graph Coloring is NP-Complete (K=3)

CO6 — 2025 Paper (10 marks)
Problem Statement

Given graph G(V,E) and integer K=3, can we color all vertices using at most 3 colors such that no two adjacent vertices have the same color? Prove this is NP-Complete.

Proof

Part 1: 3-Coloring ∈ NP

Given a coloring assignment, verify in O(V+E): for each edge (u,v), check color(u) ≠ color(v). This is polynomial → 3-Coloring ∈ NP.

Part 2: 3-Coloring is NP-Hard (reduce 3-SAT → 3-Coloring)

We show 3-SAT ≤ₚ 3-Coloring.

Construction: Given a 3-SAT formula with variables x₁,...,xₙ and clauses C₁,...,Cₘ:

  • Create 3 special nodes: T (True), F (False), B (Base) — connected to each other (triangle → need 3 colors)
  • For each variable xᵢ: create nodes xᵢ and x̄ᵢ, connect them to each other and to B. So xᵢ and x̄ᵢ get colors T or F (opposite)
  • For each clause (l₁ ∨ l₂ ∨ l₃): add a gadget graph that ensures at least one literal is colored T

Correctness: The formula is satisfiable iff the constructed graph is 3-colorable. The reduction runs in polynomial time.

Therefore 3-SAT ≤ₚ 3-Coloring → 3-Coloring is NP-Hard. Since it's in NP too → 3-Coloring is NP-Complete. □
