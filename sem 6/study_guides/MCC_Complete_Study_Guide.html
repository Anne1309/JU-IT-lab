Introduction to Multimedia

CT + Sem ▶
Core Concept Multimedia = computer-controlled integration of text, graphics, images, video, animation, and audio where every type of information can be represented, stored, transmitted, and processed digitally.
Why it matters This definition is the foundation of every exam question on "components of multimedia." The professor always asks for examples of applications — memorise 5–6 diverse ones.
Key Distinction: Multimedia vs Hypermedia

Multimedia

  • Combines text, audio, video, animation, graphics
  • Linear/sequential navigation
  • Users passively consume content
  • Limited interactivity
  • Examples: slideshows, videos, MP4, MP3

Hypermedia

  • Extension of multimedia with hyperlinks
  • Non-linear navigation via links
  • Users actively navigate content
  • Highly interactive
  • Examples: WWW, HTML, JavaScript, e-learning
Applications of Multimedia (memorise these)
  • Video teleconferencing & online education
  • Tele-medicine & healthcare monitoring
  • Augmented reality (placing computer graphics into real scenes)
  • Interactive entertainment & games
  • Co-operative work environments
  • Searching large video/image databases
  • Voice-recognition interactive environments
Professor's Pattern "What are the key components of multimedia? Name two examples of multimedia applications." — appears in EVERY semester exam. Answer = list all 6 components (text, image/graphics, audio, video, animation, interactive elements) + 2 application examples with brief explanations.

Multimedia Presentation: Sprite Animation & Video Transitions

CT + Sem ▶
Sprite Animation A sprite is a small 2D image/animation overlaid onto a background. The process: (1) Create a 1-bit mask M of the sprite (black on white). (2) AND the background B with mask M → blanks out where sprite goes. (3) OR result with sprite S → places sprite on background.

Result = (B AND M) OR S
Video Transitions — Know All 4 Types
TransitionWhat HappensFormula / Key Detail
CutAbrupt change — two frames butted togetherSimplest and most common
Fade In/OutScene gradually appears/disappears (usually to black/white)Special case of Cross Dissolve where one video is black/white
WipePixels in a region replaced by another video following a geometric patternSpecial form of Dither Dissolve
DissolveEvery pixel mixed over time between two videosTwo types: (1) Cross dissolve (2) Dither dissolve
Cross Dissolve Formula (Numerical) D = (1 − α(t)) · A + α(t) · B
Where A and B are colour 3-vectors for video A and B, and α(t) is a linear transition function α(t) = k·t (with k·t_max = 1).

Slide Transition: For VideoL sliding in from left, pushing out VideoR, the transition boundary moves: x_T = (t/t_max) · x_max. Pixel position in VideoL: x_L = x + (x_max − x_T).
Technical Design Issues
  • NTSC, PAL, SECAM video formats are not compatible — conversion required
  • Memory: at least 128 MB RAM, 20 GB hard disk for multimedia programs
  • Cross-platform software relies on run-time modules which may not work everywhere

Vector vs Raster Images — KEY COMPARISON (appears every year)

Raster (Bitmap)

  • Grid of x,y pixels — each pixel has a color value
  • Digital photos: always pixel-based
  • Efficient color blending (each pixel colored individually)
  • Loses quality when scaled up (pixelation)
  • Formats: JPEG, GIF, PNG, BMP, TIFF

Vector

  • Mathematical equations defining edges and shapes
  • Fonts and logos: always vector-based
  • Can be scaled to any size without quality loss
  • Efficient color changes
  • Formats: SVG, PostScript (PS), PDF, AI
GIF87 File Format — Detailed (appears in EVERY semester paper)

GIF = Graphics Interchange Format. Limited to 8-bit (256) color images. Best for drawings with few distinctive colors.

BlockPurpose
GIF Signature"GIF87a" — 6 characters identifying valid GIF + version number
Screen DescriptorOverall image dimensions, color map info, background color, color depth (stored as 8-bit bytes)
Global Color MapOptional but recommended; defines up to 256 colors (RGB triples)
Image DescriptorPer-image attributes — position, size, interlace flag
Raster AreaActual pixel color index values, left-to-right, top-to-bottom (or interlaced)
GIF TerminatorCharacter 0x3B (";") — signals end of file
GIF Interlacing — 4-Pass Process Pass 1: every 8th row, starting row 0. Pass 2: every 8th row, starting row 4. Pass 3: every 4th row, starting row 2. Pass 4: every 2nd row, starting row 1. This makes images appear to "come into focus" as they load — progressive rendering.
Interlaced vs Progressive Scanning

Interlaced (i)

  • Odd-numbered lines scanned first (Field 1), then even (Field 2)
  • Two fields = one frame
  • Reduces flicker with fewer "flashes" per frame
  • Can cause blurring with fast motion (lines from different times)
  • NTSC: 525 lines, 29.97fps → 59.94 fields/sec

Progressive (p)

  • Complete frame scanned top-to-bottom in one pass
  • No flickering; sharper image for moving objects
  • Higher bandwidth needed for same frame rate
  • Used in computer monitors and HDTV
  • Example: 1080p, 720p
Color Models — RGB and CMYK

RGB (Additive)

  • Used in screens, monitors, TVs
  • Adding all colors = White
  • No color = Black
  • 24-bit: 8 bits per channel

CMYK (Subtractive)

  • Used in printing
  • Cyan, Magenta, Yellow, Key (Black)
  • Adding all colors = Black
  • No color = White (paper)
Other Image Formats
  • JPEG: lossy compression with quality factor (Q); Q=10% gives 1.5% of original size
  • PNG: supersedes GIF; up to 48-bit color; supports alpha channel; 7-pass 2D progressive display
  • TIFF: Tagged Image File Format; flexible tags; originally lossless
  • EXIF: digital camera format; stores camera metadata (flash, exposure, white balance)
  • PDF: LZW compression; text + figures; 2:1 to 3:1 compression ratio
Dithering Process of juxtaposing pixels of two colors to create the illusion of a third color — used to reduce 24-bit photos to 8-bit (256 colors) for GIF. Also used in printing: replaces each pixel with a pattern of dots (e.g. 2×2 or 4×4) to simulate gray levels on 1-bit printers. Connection to halftone printing (analog process using ink circle sizes).

Audio: Digitization, Quantization & MIDI

CT + Sem ▶
Digitization of Sound Sound = pressure wave (longitudinal). To use digitally, we must convert it to numbers. Two steps: 1. Sampling — measuring amplitude at evenly spaced time intervals. Rate = sampling frequency. 2. Quantization — sampling in the amplitude/voltage dimension. Maps continuous values to discrete levels.
Nyquist Theorem — Critical for Exam
Nyquist Theorem (Sampling Theorem) "An analog signal can be converted to digital and reconstructed without error if the sampling rate ≥ 2 × the highest frequency component in the signal."

Nyquist Rate

  • Minimum sampling rate to avoid aliasing
  • Formula: Fs = 2 × F_max
  • Example: CD audio (20 kHz max) → 44.1 kHz sampling rate

Nyquist Frequency

  • Maximum frequency that won't alias for a given sampling rate
  • Formula: F_nyquist = Fs / 2
  • Also called Folding Frequency or Cutoff Frequency
  • Nyquist Interval: [-Fs/2, Fs/2]
Aliasing Formula When F_true < F_sampling < 2 × F_true:
F_alias = F_sampling − F_true
Example: If true freq = 1000 Hz and sampling rate = 1500 Hz → alias = 500 Hz (wrong, lower frequency detected).
SNR (Signal to Noise Ratio)
SNR (dB) = 20 × log₁₀(V_signal / V_noise)

SNR in decibels. 1 dB = 1/10 of a Bel. If signal voltage = 10× noise → SNR = 20 dB. Higher SNR = better quality signal.

Chroma Subsampling Humans see color with lower spatial resolution than brightness (luminance). So we can transmit less color info without perceived quality loss.

Lossless Compression Techniques

📊

Introduction to Compression & Information Theory

Core Theory ▶
Compression Ratio
Compression Ratio = B₀ / B₁
B₀ = bits before compression, B₁ = bits after. A ratio of 2 means the file is halved. Lossless = perfect reconstruction. Lossy = approximate reconstruction (higher ratios possible).
Entropy (Shannon's Information Theory)
η = H(S) = −Σ pᵢ · log₂(pᵢ)
Where pᵢ = probability of symbol sᵢ. Entropy = average minimum bits needed per symbol.

Rule: The average code length l̄ ≥ η (you can never do better than entropy).
  • High entropy → uniform (boring) distribution → hard to compress
  • Low entropy → peaked distribution → good compression possible
Entropy Calculation Example Symbols: a1=0.1, a2=0.5, a3=0.25, a4=0.15
η = −(0.1·log₂0.1 + 0.5·log₂0.5 + 0.25·log₂0.25 + 0.15·log₂0.15)
= −(0.1×(−3.32) + 0.5×(−1) + 0.25×(−2) + 0.15×(−2.74))
= 0.332 + 0.5 + 0.5 + 0.411 = 1.743 bits

Run-Length Coding (RLC)

Foundational ▶
Core Concept Instead of storing repeated values, store (value, count) pairs. Works when symbols form continuous runs (groups).

Example: AAAAABBBCC → (A,5)(B,3)(C,2) — 10 chars → 6 values.
How to calculate RLC compressed size: For each distinct run: store the pixel value + the run length. If pixel = 1 byte and count = 1 byte, each pair = 2 bytes. Compare to original (1 byte per pixel × total pixels).
When RLC is most useful Images with large uniform areas (like scanned text, fax images, binary images). Used as a step inside JPEG (for AC coefficients after DCT and quantization).

Shannon-Fano & Huffman Coding

🔥 High Priority — Every Year ▶
Shannon-Fano Algorithm (Top-Down)
Algorithm Steps:
  1. Sort symbols by frequency (highest to lowest)
  2. Recursively divide into two groups with approximately equal total counts
  3. Assign 0 to upper half, 1 to lower half
  4. Repeat until each group has one symbol
Example: "HELLO" — Shannon-Fano Symbols sorted: L(2), H(1), E(1), O(1) — total=5 
Split 1: [L,H,E,O] → [L(2)] vs [H,E,O(3)]  (split at ≈2.5)
Split 2: [H,E,O] → [H(1)] vs [E,O(2)]
Split 3: [E,O] → [E(1)] vs [O(1)]

Result: L=0 (1 bit), H=10 (2 bits), E=110 (3 bits), O=111 (3 bits)
Total bits = 2×1 + 1×2 + 1×3 + 1×3 = 2+2+3+3 = 10 bits
Entropy = −(2/5·log₂(2/5) + 3×1/5·log₂(1/5)) = 1.922 bits/symbol → 5×1.922 ≈ 9.6 bits (optimal)
Huffman Coding Algorithm (Bottom-Up) — THE KEY ALGORITHM
Algorithm Steps:
  1. Initialization: Put all symbols on a list sorted by frequency
  2. Repeat until one symbol left:
    • Pick 2 symbols with LOWEST frequency
    • Make them children of a new parent node
    • Parent's frequency = sum of children's
    • Insert parent back into sorted list, delete children
  3. Assign codes: Trace paths from root — left=0, right=1 (or higher=0, lower=1 per professor's convention)
Full Huffman Example: "HELLO" (5 symbols: L=2, H=1, E=1, O=1) 
Step 1 (sorted): L(2)  H(1)  E(1)  O(1)
Step 2a: Combine H(1)+E(1) → P1(2)
         List: L(2)  P1(2)  O(1)
Step 2b: Combine P1(2)+O(1) → P2(3)
         List: L(2)  P2(3)
Step 2c: Combine L(2)+P2(3) → P3(5) = ROOT

Tree:       P3(5)
           /     \
        L(2)    P2(3)
               /    \
           P1(2)   O(1)
           /    \
         H(1)  E(1)

Codes: L=0, H=100, E=101, O=11  (using higher prob=0 convention)
OR:    L=0, H=110, E=111, O=10  (alternately)

Average code length = (2×1 + 1×3 + 1×3 + 1×2)/5 = 9/5 = 1.8 bits/symbol
Total bits for HELLO = 1+3+1+1+2 = 8 bits (or similar)
Calculating Entropy, Average Code Length, Coding Efficiency For symbols with occurrences: a1=3003, a2=996, a3=2017, a4=1487, a5=2497 (total=10000) 
Probabilities: p1=0.3003, p2=0.0996, p3=0.2017, p4=0.1487, p5=0.2497

Entropy η = −Σ pᵢ·log₂(pᵢ)
= −(0.3003×log₂0.3003 + 0.0996×log₂0.0996 + ...)
≈ 2.236 bits/symbol (calculate each term)

Coding Efficiency = η / l̄ × 100%
where l̄ = average Huffman code length = Σ pᵢ × (code length for sᵢ)
Properties of Huffman Coding
  • Unique Prefix Property: No code is a prefix of another → unambiguous decoding
  • Optimality: Minimum redundancy for a given probability distribution
  • Two least frequent symbols have the same code length (differ only at last bit)
  • More frequent symbols → shorter codes
  • Average code length: η ≤ l̄ < η + 1
Professor's Pattern This is the MOST numerically tested topic. The APPLE example (A=0.2, P=0.4, L=0.2, E=0.2) appears in BOTH 2023 and 2024 papers. The 5-symbol frequency table (a1=3003, a2=996...) also appears in both years. You MUST be able to: (a) build the Huffman tree, (b) calculate entropy, (c) calculate average code length, (d) calculate coding efficiency, (e) compare Shannon-Fano vs Huffman efficiency.

LZW Compression (Dictionary-Based Coding)

🔥 Must-Know Numerical ▶
Core Concept LZW uses fixed-length codewords to represent variable-length strings that commonly occur together. Both encoder and decoder build the same dictionary dynamically from the data — no need to transmit the dictionary!
LZW Compression Algorithm
BEGIN
  s = next input character
  while not EOF {
    c = next input character
    if s+c exists in dictionary → s = s+c (extend string)
    else {
      output the code for s
      add string s+c to dictionary with new code
      s = c
    }
  }
  output the code for s
END
Classic Example: "MISSISSIPPI" (Initial table: M=1, S=2, I=3, P=4) 
Step | s  | c  | s+c in dict? | Output | Add to dict
  1  | M  | I  | MI? No       | 1(M)   | MI=5
  2  | I  | S  | IS? No       | 3(I)   | IS=6
  3  | S  | S  | SS? No       | 2(S)   | SS=7
  4  | S  | I  | SI? No       | 2(S)   | SI=8
  5  | I  | S  | IS? YES      | —      | s=IS
  6  | IS | S  | ISS? No      | 6(IS)  | ISS=9
  7  | S  | I  | SI? YES      | —      | s=SI
  8  | SI | P  | SIP? No      | 8(SI)  | SIP=10
  9  | P  | P  | PP? No       | 4(P)   | PP=11
 10  | P  | I  | PI? No       | 4(P)   | PI=12
 11  | I  | —  | EOF          | 3(I)   | 

Output codes: 1 3 2 2 6 8 4 4 3
Original: 11 characters → 9 codes
Compression ratio = 11/9 ≈ 1.22
LZW Decompression Algorithm
BEGIN
  s = NIL
  while not EOF {
    k = next input code
    entry = dictionary[k]
    output entry
    if s != NIL → add string s+entry[0] to dictionary with new code
    s = entry
  }
END
Professor's Pattern "Execute LZW compression and decompression on the string MISSISSIPPI where string table is M=1, S=2, I=3, P=4" appears in BOTH 2023 and 2024 semester papers (8 marks). You must show the FULL step-by-step table for both compression and decompression. Practice until you can do this from memory.

Arithmetic Coding

🔥 15-mark Numerical ▶
Core Concept Represents the entire message as a single number in [0,1). Unlike Huffman (which assigns integer-bit codewords), arithmetic coding can achieve exactly entropy. A message is represented by a half-open interval [low, high) that narrows as more symbols are encoded.
Arithmetic Coding Encoder
low = 0.0;  high = 1.0;  range = 1.0
for each symbol:
  low  = low + range × Range_low(symbol)
  high = low + range × Range_high(symbol)  ← NOTE: use NEW low
  range = high - low
Output: any value in [low, high), typically (low+high)/2 as tag
Classic Encoding Example: "DEAFS" Symbol table: A=[0,0.2), B=[0.2,0.3), C=[0.3,0.5), D=[0.5,0.55), E=[0.55,0.85), F=[0.85,0.9), $=[0.9,1.0) 
Symbol | low        | high       | range
Start  | 0          | 1.0        | 1.0
D      | 0+1×0.5=0.5| 0.5+1×0.05=0.55 | 0.05
E      | 0.5+0.05×0.55=0.5275 | 0.5+0.05×0.85=0.5425 | 0.015
A      | 0.5275+0.015×0=0.5275 | 0.5275+0.015×0.2=0.530 | 0.003
F      | 0.5275+0.003×0.85=0.530 | 0.5275+0.003×0.9=0.5302 | 0.00015
$      | 0.530+0.00015×0.9=... | ... | ...

Tag = (low + high) / 2 → convert to binary for transmission
Arithmetic Decoding
Convert received binary code to decimal tag value
Loop:
  Find symbol s such that Range_low(s) ≤ tag < Range_high(s)
  Output s
  low = Range_low(s);  high = Range_high(s)
  range = high - low
  tag = (tag - low) / range   ← rescale tag
Until terminator symbol found
Decoding Example: String "EAOU" (from 2023 paper) Symbol table: A=0.12, E=0.42, I=0.09, O=0.3, U=0.07 
Ranges: A=[0, 0.12), E=[0.12, 0.54), I=[0.54, 0.63), O=[0.63, 0.93), U=[0.93, 1.0)

Encoding "EAOU":
  E: low=0.12, high=0.54, range=0.42
  A: low=0.12+0.42×0=0.12, high=0.12+0.42×0.12=0.1704, range=0.0504
  O: low=0.12+0.0504×0.63=0.1518, high=0.12+0.0504×0.93=0.1687, range=0.0169
  U: low=0.1518+0.0169×0.93=0.1675, high=0.1518+0.0169×1.0=0.1687

Tag = (0.1675+0.1687)/2 = 0.1681 → convert to binary
Professor's Pattern Arithmetic coding encoding AND decoding on "EAOU" appears in 2023 (Q5, 10 marks). In 2024 it's "DEAFS" (Q9, 12 marks) with a different symbol table. This is a guaranteed numerical question worth 10–15 marks. Practice the encode-decode cycle fully. The tag value = (low+high)/2.

Distortion Measures: MSE, SNR, PSNR

Numerical ▶
Why Lossy? Lossless compression ratios are too low for multimedia (typically 2:1 to 3:1). Lossy compression achieves much higher ratios (10:1 to 50:1+) by allowing controlled data loss — humans can't perceive small quality reductions.
Distortion Measures (for image quality assessment)
MSE = (1/N) × Σ(xₙ − yₙ)²
SNR = 10 × log₁₀(σ²ₓ / σ²d)
PSNR = 10 × log₁₀(MAX² / MSE)
Where: xₙ = original data, yₙ = reconstructed data, N = length, MAX = maximum pixel value (255 for 8-bit). Higher PSNR = better quality reconstruction.
Example Calculation (from 2023 paper Q7) For a 4×4 original vs reconstructed image array: 
1. Compute difference matrix: s[i,j] = original[i,j] − reconstructed[i,j]
2. MSE = Σ(s[i,j])² / (4×4) = sum of all squared differences / 16
3. SNR = 10·log₁₀(mean of original² / MSE)
4. PSNR = 10·log₁₀(255² / MSE) = 20·log₁₀(255) − 10·log₁₀(MSE)

Quantization

Core Concept ▶
Quantization The main source of "loss" in lossy compression. Reduces the number of distinct output values to a much smaller set. Maps continuous or high-precision input values to fewer discrete output levels.
TypeDescriptionUsed In
Uniform (Midrise)Equal step sizes; reconstruction level at middle of intervalPCM, basic digital audio
Uniform (Midtread)Equal step sizes; reconstruction level at the tread (includes zero)Similar to midrise
Nonuniform (Companded)Nonuniform steps; finer resolution for small values; uses μ-law or A-lawTelephone/speech (64 kbps)

Lloyd-Max QuantizerAnalytically optimal nonuniform quantizer using least-squares minimizationDPCM for speech/audio
Rate-Distortion Theory Provides the analytical framework for lossy compression: Rate (bits/sample) vs Distortion (error). As rate decreases, distortion increases. The R(D) function shows the theoretical minimum achievable distortion for a given bit-rate — no compression can do better.

DCT (Discrete Cosine Transform) & Transform Coding

Foundation of JPEG/MPEG ▶
Why Transform Coding? If we transform input X to Y using a linear transform T such that Y's components are less correlated, then Y can be coded more efficiently. Most information concentrates in a few transform coefficients — the rest can be coarsely quantized or zeroed out with minimal quality loss.
DCT Key Properties
  • Spatial frequency: how many times pixel values change across an image block
  • DC component (F(0,0)) = average of the block
  • AC components = spatial frequency details
  • DCT is a linear transform — uses only cosine basis functions (real part of DFT)
  • Energy compaction: most energy concentrates in low-frequency (top-left) coefficients
2D DCT Formula (8×8 block)
F(u,v) = (C(u)C(v)/4) × Σᵢ Σⱼ cos((2i+1)uπ/16) · cos((2j+1)vπ/16) · f(i,j)
where C(0)=1/√2, C(u)=1 for u≠0. Inverse DCT (IDCT) reconstructs f(i,j) from F(u,v). The 2D DCT can be separated into two 1D DCTs (separability) — reduces computation from 64 to 16 operations per coefficient.
KLT (Karhunen-Loève Transform) Optimal transform that uses eigenvectors of the autocorrelation matrix. Perfectly decorrelates input components. Disadvantage: signal-dependent (must compute eigenvectors for each dataset) → computationally expensive. DCT is a good fixed approximation to KLT for natural images.
🌊

Wavelet-Based Coding

CO3 + JPEG-2000 ▶
Key Idea Wavelet transform decomposes a signal into components localized in both time (space) and frequency — unlike DCT which only gives frequency information. The basis functions (wavelets) are scaled and translated versions of a "mother wavelet" ψ.
Types
  • CWT (Continuous Wavelet Transform): continuous scale and shift — theoretical framework
  • DWT (Discrete Wavelet Transform): discrete steps — practical implementation using filter banks
  • Haar Wavelet: simplest wavelet — pairwise averaging and differencing
2D DWT Subbands After one level of 2D DWT, the image is divided into 4 subbands: LL (low-low = approximation), HL (high-low), LH (low-high), HH (high-high). The LL subband can be recursively decomposed for multi-level analysis.
Haar Transform Example Given sequence {10, 13, 25, 26}:
Averages: x̄₁=(10+13)/2=11.5, x̄₂=(25+26)/2=25.5
Differences: d₁=(10-13)/2=-1.5, d₂=(25-26)/2=-0.5
Transformed: {11.5, 25.5, -1.5, -0.5} — same number of elements, reversible!
Why wavelets beat DCT DCT operates on fixed 8×8 blocks → "blocky" artifacts at high compression. Wavelets operate globally → smooth compression with no block boundaries. This is why JPEG-2000 uses wavelets instead of DCT.

JPEG Standard — Complete Walkthrough

🔥 Every Semester ▶
What is JPEG? Joint Photographic Experts Group. Accepted as international standard in 1992. Lossy image compression using DCT. Uses psychophysical observations about human vision to achieve compression.
3 Key Observations Behind JPEG
  1. Spatial Redundancy: Useful image content changes slowly across the image — intensity rarely varies widely within an 8×8 block → can discard high spatial frequencies
  2. Psychophysics: Humans are much less likely to notice loss of high spatial frequency components than low frequencies → aggressively quantize high frequencies
  3. Chroma Sensitivity: Visual acuity for gray is much greater than for color → use 4:2:0 chroma subsampling
JPEG Compression Steps (All 5 must be known)
StepWhat HappensWhy
1. Color Space ConvertRGB → YIQ or YUV; subsample chroma (4:2:0)Humans less sensitive to color detail
2. DCT on 8×8 blocksEach 8×8 block → 64 DCT coefficients F(u,v)Converts spatial info to frequency domain; energy compaction
3. QuantizationF̂(u,v) = round(F(u,v) / Q(u,v))MAIN SOURCE OF LOSS; larger Q values for high frequencies
4. Zig-Zag + RLC on AC8×8 matrix → 64-vector via zig-zag scan; encode as {skip-zeros, value} pairsZig-zag groups near-zero high-freq coefficients at end for long zero runs
5. DPCM on DC + EntropyDC coefficients: DPCM. All coefficients: Huffman codingDC changes slowly between blocks; Huffman compresses variable-length codes
Quantization Detail The quantization matrix Q(u,v) has larger values in bottom-right (high frequencies) → more loss at high frequencies. For DC (0,0): Q=16, For high AC: Q up to 99. Larger Q entry = coarser quantization = more loss = higher compression = lower quality.
4 JPEG Modes
ModeHow it works
Sequential (Baseline)Default; single left-to-right, top-to-bottom scan; whole image encoded once
ProgressiveMultiple scans — spectral selection (DC first, then ACs in bands) OR successive approximation (MSBs first). Image improves in quality with each scan.
HierarchicalMultiple resolutions — encode at lowest resolution first, then add detail differences. Similar to progressive but spatially.
LosslessTruly lossless mode; now replaced by JPEG-LS

"What are 4 commonly used JPEG modes" — 3 marks. Draw the JPEG encoder block diagram for full marks: RGB→YUV→DCT→Quantization→Zig-Zag+RLC→DC DPCM→Huffman Coding.

MPEG Video Coding Standards

CO4 Theory ▶
MPEG Overview Moving Pictures Experts Group, established 1988. MPEG defines only the compressed bitstream and decoder — encoders are left to manufacturers. Three frame types used for temporal compression.
Frame Types in MPEG — Critical
TypeNamePredictionSizeCompression
I-frameIntra-codedNone — coded independently like JPEG~18 kB7:1
P-framePredictedForward from previous I or P frame~6 kB20:1
B-frameBidirectionalForward AND backward from reference frames; average if both succeed~2.5 kB50:1
Motion Estimation (ME) & Motion Compensation (MC) ME: Find the best matching macroblock (16×16) in a reference frame for each macroblock in the target frame. Only the difference (prediction error) + motion vector (MV) is transmitted. MC: Use the motion vector to predict the frame content. B-frames can have up to 2 MVs (forward + backward).

Audio Compression: MP3 & Psychoacoustics

Short Notes ▶
Psychoacoustics The study of how humans perceive sound. Key effects exploited in audio compression:
  • Masking: A loud sound "masks" nearby quieter sounds we can't hear
  • Frequency Masking: Louder tone at one frequency masks softer tones at nearby frequencies (same time)
  • Temporal Masking: Loud sound masks softer sounds just before (pre-masking) and just after (post-masking) it in time
MP3 (MPEG-1 Layer 3) Uses psychoacoustic model to identify and discard inaudible frequencies. Process: 1. Filter bank: divide audio into 32 frequency subbands 2. Psychoacoustic model: compute masking thresholds per subband 3. Quantize each subband — use fewer bits for masked (inaudible) subbands 4. Huffman encode the quantized values Typical: CD audio (1411 kbps) → MP3 128 kbps (11:1 ratio) with acceptable quality.
ADPCM G.722 uses ADPCM for wideband speech at 64 kbps. The ITU G.711 standard uses μ-law (USA/Japan) or A-law (Europe) companding for telephone quality audio at 64 kbps.
Professor's Pattern "Differentiate MP3 vs MPEG" = 4 marks (2023 Q9b). Key distinction: MP3 is only audio compression (part of MPEG-1 Layer 3); MPEG includes both video and audio compression at various quality levels. MPEG-4 audio supports speech at 2–24 kbps and high quality audio at 16–64 kbps per channel.
